# G DEV. F.C. Homepage

레트로 아케이드 콘솔 컨셉의 게임 개발 동아리 홈페이지.
Next.js 15 App Router + 정적 export(`output: 'export'`)로 빌드되며, 서버 없이 어디서나 호스팅할 수 있습니다.

## 실행

```bash
npm install
```

```bash
npm run dev
```

```bash
npm run build
```

빌드 결과는 `out/` 에 순수 HTML/CSS/JS 로 생성됩니다. GitHub Pages, Netlify, Vercel, S3 등에 그대로 올리면 됩니다.

## 화면 구성

| 경로 | 화면 | 설명 |
|---|---|---|
| `/` | 타이틀 | `PRESS START` — 클릭 또는 Enter/Space. 배경에 반짝이는 스타필드 + 우주선 |
| `/select` | SELECT MODE | 언덕 도시의 계단 광장 — 캐릭터 7명이 각자 장소에서 idle, 클릭/Enter 로 진입 |
| `/about` | ABOUT | 매니페스토 히어로 · SEASON 1 · HISTORY · ACTIVITIES · CONTACT |
| `/showcase` | SHOWCASE | 프로젝트 슬롯 6칸 (← → 이동, 스와이프) |
| `/join` | JOIN THE PARTY | RPG 캐릭터 생성 컨셉 지원 폼 (실시간 카드 미리보기) |
| `/play` | PLAY | "달려라 우왕이" 미니게임 — 교실 탈출 + 횡스크롤 러닝 + 공개 오락실 랭킹 |
| `/gallery` | GALLERY | 회원 전용 갤러리 — 여러 장 업로드, 목록은 대표사진만, 클릭 시 상세 페이지에서 전체 스크롤 |
| `/events` | 캘린더 | 점성술사의 천막 컨셉. 구글 시트 연동 행사 목록 — 카드/달력 보기, 검색, 분류 필터 |
| `/board` | BOARD | 회원 전용 게시판 — 카테고리(색상 구분, 공지는 항상 상단 고정), 사진/파일 첨부, 댓글, 선택적 투표 |

프레임은 항상 뷰포트를 가득 채우며, 내부 콘텐츠만 `--content-max` 로 폭이 제한됩니다.
`/play` 처럼 그 제한 없이 패널 폭 전체를 써야 하는 화면은 `<Frame fullBleedBody>` 를 씁니다.
`fullBleedBody` 는 동시에 `.page` 에 실제 높이(`height:100dvh`)를 씌워, 내부에 자체
스크롤 영역(예: 인트로 화면)이 있는 페이지에서 그 스크롤이 문서 전체 스크롤로 새는
문제를 막습니다 — `min-height` 만으로는 상한이 없어 flex 자식들이 그냥 늘어나 버립니다.
홈 화면의 스타필드처럼 헤더까지 포함해 패널 전체를 채우는 배경은 `<Frame background={...}>` 로 넣습니다.

## 캘린더 · Google Sheets

화면 컨셉은 **점성술사의 천막**입니다. 배경은 `components/TentScene.tsx` 가 저해상도 캔버스로
천막 천·매달린 등불·별자리·떠오르는 입자·수정구슬을 그리고(홈의 `GateScene`, 게시판의
`CampfireScene` 과 같은 기법), 화면 안의 색은 `app/events/events.module.css` 상단에 모아둔
보라/금빛/수정구슬 지역 변수(`--tent-*`)로 통일합니다. 달력 막대 색은
`lib/eventCalendar.ts` 의 `eventColor()` 가 분류별로 고정 배정하며, 등록되지 않은 분류는
같은 팔레트 안에서 제목 해시로 결정합니다(같은 행사는 항상 같은 색).

`data/events-source.json`의 `sheetId`에 연결할 시트 ID를 지정합니다. `sheetName`이 비어 있으면
기본 탭을 읽으며, 특정 탭을 사용하려면 탭 이름을 입력합니다. 현재는 제공받은 행사 시트의 `events` 탭에 연결되어 있습니다.
시트는 로그인 없이 읽을 수 있어야 하며, 읽기 전용 Google Visualization CSV 응답을 사용합니다.
설명: [Google Sheets 데이터 소스 및 접근 권한](https://developers.google.com/chart/interactive/docs/spreadsheets).

현재 `events` 탭의 영문 열 `title`, `category`, `start_date`, `end_date`, `location`, `url`을 지원합니다.
시작일과 종료일은 기간으로 표시하고, `jam` 분류는 게임잼으로 표시합니다. `source`는 주최 기관으로 간주하지 않습니다.
선택 항목인 `organizer`, `summary`도 지원합니다. 기존 한글 열 형식도 아래와 같이 사용할 수 있습니다.

첫 행에는 열 이름을 넣고, 두 번째 행부터 행사 하나당 한 행을 작성합니다.
열 순서는 바꿔도 되며, 추가 열은 무시합니다. 외부 수집 에이전트도 이 형식으로 기록하면 됩니다.

| 열 | 용도 |
|---|---|
| 행사명 | 필수. 비어 있는 행은 표시하지 않음 |
| 분류 | 게임잼, 전시회, 컨퍼런스 등. 비어 있으면 기타 |
| 일정 | 표시할 날짜/기간 문자열 |
| 장소 | 장소 또는 온라인 안내 |
| 주최 | 주최 기관 |
| 소개 | 행사 소개. 셀 내 줄바꿈 지원 |
| 링크 | 행사 상세 페이지의 전체 http/https 주소 |

사이트는 페이지 진입과 게시판의 **새로고침** 버튼 클릭 시 시트를 다시 읽습니다.
**카드 보기 / 달력 보기**를 전환할 수 있으며 검색과 분류 조건은 두 보기에 공통으로 적용됩니다.
카드는 페이지당 12개씩 표시하며 하단 페이지 번호는 1–5, 6–10처럼 최대 5개씩 표시합니다.
이전/다음 버튼으로 페이지 묶음을 넘어갈 수 있고, 검색·분류 변경 및 데이터 새로고침 시 첫 페이지로 이동합니다.
월간 달력은 행사마다 일정한 색상을 부여하고 시작일과 종료일을 포함한 전체 기간을 표시합니다.
이전/다음 달, 이번 달 이동을 지원합니다. 날짜는 `YYYY-MM-DD` 또는 `YYYY-MM-DD ~ YYYY-MM-DD` 형식으로 읽으며,
해석할 수 없는 일정은 달력에서 제외하고 카드 보기에서 확인하도록 안내합니다.
행사 데이터 변경에는 사이트 재배포가 필요하지 않으며, Google 측 반영 지연이 있을 수 있습니다.
시트 ID나 탭 설정을 변경하면 사이트를 다시 빌드해야 합니다.
빈 시트는 빈 게시판으로 표시하고, 데이터가 있지만 `행사명` 또는 `title` 열이 없거나 접근이 실패하면 재시도를 안내합니다.
시트 수정 기능이나 외부 수집 에이전트는 이 사이트에 포함하지 않습니다.

## 회원 로그인 · 갤러리 · 게시판 (Supabase)

`/gallery`, `/board` 는 회원가입 없이 운영자가 미리 발급한 "요원 코드네임" 계정(예: `PIXEL-07`)으로만
접근할 수 있는 회원 전용 화면입니다. 정적 export(`output: 'export'`)는 그대로 유지하고, 브라우저에서
[Supabase](https://supabase.com)의 Auth · Postgres · Storage API를 직접 호출하는 구조입니다 — Next.js
서버가 없어도 동작합니다. 실제 접근 제어는 페이지 라우트가 아니라 Supabase Row Level Security가
담당하므로 (`supabase/schema.sql`), 로그인하지 않으면 어떤 데이터 쿼리도 빈 값이 돌아옵니다.

### 1. Supabase 프로젝트 준비

1. [supabase.com](https://supabase.com)에서 무료 프로젝트를 생성합니다.
2. **SQL Editor**에서 `supabase/schema.sql` 전체 내용을 실행합니다 (테이블 + RLS 정책).
3. 이어서 `supabase/migrations/` 폴더의 파일들을 **번호 순서대로** SQL Editor에서 실행합니다
   (게시판 카테고리/첨부파일, 갤러리 다중 이미지, `board-attachments` 버킷을 추가합니다 —
   `gallery` 버킷과 달리 이 버킷은 마이그레이션 SQL이 자동으로 만듭니다).
4. **Storage**에서 `gallery` 버킷을 **Private**으로 생성합니다 (`board-attachments`는 3번에서 이미 생성됨).
5. **Project Settings → API**에서 값을 확인합니다.

### 2. 환경변수

`.env.local` (git에 커밋되지 않음, 브라우저에 노출되어도 안전한 anon key만 사용):

```bash
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...
```

Vercel에 배포한다면 **Project Settings → Environment Variables**에도 동일하게 등록해야
정적 빌드에 값이 반영됩니다.

`.env.script.local` (계정 생성 스크립트 전용, **service_role key는 절대 커밋/공유 금지**):

```bash
SUPABASE_URL=https://xxxxxxxx.supabase.co
SUPABASE_SERVICE_ROLE_KEY=eyJ...
```

### 3. 회원 100계정 일괄 생성

```bash
npm run gen:members
```

- 첫 계정은 항상 `CHESS-01` (마스터 어드민 — 다른 회원의 글/댓글/업로드도 삭제 가능).
- 나머지는 게임/게임업계 용어 기반 코드네임(`PIXEL-07`, `RESPAWN-19`, `GLITCH-42` 등)으로 최대 99개 생성.
- 결과는 `scripts/output/members-credentials.csv` (codename, password, role)로 저장됩니다 —
  이 파일은 `.gitignore`에 포함되어 있으니, 동아리원에게 개별 배포한 뒤 로컬에서 지우세요.
- 이미 존재하는 코드네임은 건너뛰므로 재실행해도 안전합니다 (인원이 늘면 다시 실행).

### 4. 로그인 방식

로그인 폼은 "코드네임 + 비밀번호"만 받고, 내부적으로 `codename@members.gdevfc.local` 형태의
합성 이메일로 Supabase Auth에 로그인합니다 (`lib/auth.ts`, `components/AuthProvider.tsx`).
세션은 Supabase가 브라우저 localStorage에 자동으로 저장·갱신합니다.

## 콘텐츠 수정 — `data/*.json`

모든 텍스트와 목록은 JSON에 있습니다. 컴포넌트를 건드릴 필요가 없습니다.

| 파일 | 내용 |
|---|---|
| `data/site.json` | 사이트 타이틀, 태그라인, 상단 시스템 바 문구, 메타 정보 |
| `data/modes.json` | SELECT MODE 카드 3종 (라벨 · 링크 · 이미지 · 스프라이트) |
| `data/about.json` | 히어로 문구, SEASON 1 매니페스토, HISTORY, ACTIVITIES, CONTACT |
| `data/showcase.json` | 프로젝트 슬롯 목록과 NO DATA 안내 문구 |
| `data/join.json` | 캐릭터 생성 필드, CLASS/장르 목록, Formspree 엔드포인트, 완료 메시지 |
| `data/play.json` | 미니게임 인트로 문구, 조작법, 페이즈 설명, 가로모드 안내, 게임오버 문구 |

### ABOUT 히어로 문구

`data/about.json` 의 `hero.lines` 가 순차 등장하는 매니페스토입니다.
`text` 배열의 각 원소가 한 줄이 되고, `tone` 이 색을 결정합니다 (`off` 오프화이트 · `lime` · `magenta`).
화면을 클릭하면 애니메이션을 건너뛰고 전체가 즉시 표시됩니다.

### 지원 폼 CLASS 추가

`data/join.json` 의 `classes` 배열에 항목을 넣으면 카드형 버튼과 미리보기 색이 함께 늘어납니다.

```json
{ "id": "writer", "label": "시나리오", "en": "WRITER", "icon": "✎", "color": "#ffb347" }
```

`color` 는 선택 시 카드 테두리 · 아바타 · 장르 칩에 그대로 반영됩니다.

### 프로젝트 슬롯 채우기

`data/showcase.json` 의 슬롯은 기본값이 전부 `null` 이라 **NO DATA** 상태로 표시됩니다.
값을 채우면 자동으로 실제 프로젝트 카드로 바뀝니다.

```json
{
  "id": "slot-01",
  "title": "프로젝트명",
  "summary": "한 줄 소개",
  "genre": "액션 로그라이크",
  "period": "2025.03 – 2025.08",
  "image": "/images/project-01.png"
}
```

슬롯 개수는 배열 길이를 늘리거나 줄이면 됩니다. 우측 상단 카운터(`01/06`)와 하단 도트가 자동으로 따라갑니다.

### 캐릭터 카드 이미지

`data/modes.json` 의 `image` 가 `null` 이면 `components/Sprite.tsx` 의 내장 픽셀 스프라이트(기사 · 마법사 · 엘프 아처 · 우왕이)가 렌더링됩니다.
직접 만든 도트 아트를 쓰려면 `public/images/` 에 넣고 경로를 지정하세요.

```json
{ "id": "about", "image": "/images/mode-about.png", "sprite": "knight" }
```

이미지 로딩에 실패하면 자동으로 내장 스프라이트로 되돌아갑니다.

### SELECT MODE — 계단 광장

`/select` 는 카드 캐러셀이 아니라 **언덕 도시의 계단 광장**입니다. 화면 앞쪽이 분수가 있는 아래 광장이고,
가운데 큰 돌계단을 오르면 난간을 두른 윗마당과 시계탑 문루가 나옵니다. 그 뒤로 윗마을이 층층이 올라가고,
맨 뒤에는 절벽 위의 성과 하늘을 가로지르는 돌다리 · 폭포가 있습니다. 하늘에는 용이 지나갑니다.

그림은 전부 **미리 구워 둔 픽셀 아트 이미지**입니다 (960x540). `art/plaza/` 의 스크립트가 그리고
`public/art/plaza/` 에 저장합니다.

```bash
npm run art        # 여섯 시간대 전부 다시 굽기 (10초쯤)
```

| 파일 | 내용 |
|---|---|
| `sky-<시간대>.png` | 하늘 · 별 · 해 · 달 |
| `clouds-<시간대>.png` | 흘러가는 구름 한 겹 (가로로 이어 붙는다) |
| `back-<시간대>.png` | 먼 산 · 성 · 윗마을 · 윗마당 건물 |
| `front-<시간대>.png` | 난간 · 옹벽 · 큰 계단 · 아래 광장 바닥 |
| `sprites-<시간대>.png` | 소품 · 불꽃 · 용 등을 모은 시트 |
| `people.png` | 마을 사람 · 주인공의 모든 프레임 (시간대와 무관 — 화면이 받은 뒤 시간대 색으로 칠한다) |

시간대는 접속 기기의 시각으로 정합니다: 새벽 · 아침 · 점심 · 오후 · 저녁 · 심야. 저녁부터 새벽까지는
창과 등불이 켜지고 등 둘레 바닥이 따뜻하게 밝아집니다. 계절은 가을 고정입니다.

`components/PlazaScene.tsx` 는 이 조각들을 겹치고 움직이는 것만 매 프레임 다시 그립니다 — 구름, 용,
폭포, 깃발, 굴뚝 연기, 화롯불, 분수, 나뭇잎, 마을 사람 29명, 주인공 7명, 낙엽, 실제 시각을 가리키는
시계 바늘, 우왕이의 TV 화면. `components/ModePlaza.tsx` 는 주인공 자리에 보이지 않는 버튼(클릭 · 키보드 ·
이름표 · 머리 위 표식)만 얹습니다.

**사람 그리기 — 입체 뼈대** (`art/plaza/rig.js` · `npcs.js` · `heroes.js`)

사람은 2D 로 한 장씩 그리지 않고, 관절을 3차원에 세운 뒤 몸 · 옷 · 머리카락 · 소지품을 타원체 · 둥근
막대 · 상자로 입혀 **보는 방향으로 돌려 픽셀로 찍습니다** (픽셀마다 깊이를 기억해 앞이 뒤를 가린다).
그래서 같은 사람을 정면 · 3/4 앞 · 옆 · 3/4 뒤 · 뒷모습 다섯 방향으로 그리고, 왼쪽을 보는 셋은 뒤집어 씁니다.
얼굴은 앞에서만, 뒷머리 · 망토 · 등짐은 뒤에서 보입니다.

- 걷기 8프레임: 디딘 발은 몸 좌표에서 일정한 속도로 뒤로 밀려납니다. 화면은 걸은 거리로 프레임을 넘기므로
  (한 바퀴 = `CYCLE` x 몸 크기) **발이 바닥에 붙어 미끄러지지 않습니다.** 굽기가 이것을 검사합니다.
- 서기 2프레임(숨쉬기 — 어깨와 머리가 1픽셀 내려감) + 손짓 2프레임(말하는 사람).
- 멀리 있을수록 작게 — 크기 단계 5개(0.62 ~ 1.0)를 따로 그리고, 걸어서 앞뒤로 움직이면 단계를 바꿔 씁니다.

**마을 사람의 움직임** — `art/plaza/nav.js` 가 걸을 수 있는 곳의 지도(4픽셀 칸)를 만들고, 화면은 그 위에서
길을 찾아(A*) 걷게 합니다. 걷는 사람은 볼거리(좌판 앞 · 분수 둘레 · TV 앞 · 과녁장 · 계단 아래 …)를 골라
걸어가 잠시 구경하고, 윗마당 사람은 집 문으로 들어갔다 나오고, 몇 명은 큰 계단을 오르내립니다.

## 지원 폼 (Formspree)

엔드포인트는 `data/join.json` 의 `formspreeEndpoint` 에 있습니다.

```json
"formspreeEndpoint": "https://formspree.io/f/xoeaaddw"
```

제출은 `fetch` 로 비동기 전송되며, 페이지 이동 없이 **`▸ CHARACTER SAVED`** 확인 화면으로 전환됩니다.
전송 실패 시 에러 문구가 뜨고 입력값은 유지됩니다.

전송되는 키는 `name` · `playerId` · `phone` · `email` · `class` · `favoriteGame` · `genre` · `originStory` · `inventory` 입니다.
`phone` · `email` 은 지원자에게 연락하기 위한 필수 항목입니다.
INVENTORY 는 파일 업로드가 아니라 **URL 텍스트**로만 전송됩니다 (무료 플랜은 첨부를 지원하지 않음).

## 미니게임 — 달려라 우왕이 V2 (`/play`)

쿠키런식 러너. 저해상도 가상 캔버스(384×216)를 비율 그대로 화면에 맞춰 확대하고, HUD ·
구간 배너 · 일시정지 · 결과 카드는 그 위에 사이트 톤(딥 차콜 · 라임/마젠타 · 픽셀 폰트)의
DOM 으로 얹습니다. 물리 · 코스는 `lib/run/`, 화면은 `components/run/RunGame.tsx`.

- **흐름**: 소개 → 캐릭터 고르기 → 달리기. 결과 · 일시정지 화면에서 캐릭터를 바꿀 수 있고, 마지막으로
  고른 캐릭터를 기억합니다(`localStorage` 키 `gdevfc_run_character`).
- **캐릭터 — 충북대 마스코트 여섯 명** (`lib/run/characters.ts`, 그림은 `components/Sprite.tsx`):
  | 캐릭터 | 능력 |
  |---|---|
  | 우왕이 | **우왕!** — 아이템 지속시간 1.5배 |
  | 좌왕이 | **3단 점프** — 몸이 작아(충돌 키 12px) 현수막 밑은 슬라이드 없이 지나간다 |
  | 스테디 | **학구열** — 학점 점수 1.5배, 족보를 들고 시작 |
  | 타나 | **불꽃 대시** — `Shift`/`X`/`DASH` 버튼으로 0.45초 동안 중력 없이 2.2배로 돌진, 장애물을 부수고 구덩이를 건넌다 (6초마다) |
  | 느루 | **광합성** — 체력 감소 30% 느리게, 하트 회복 1.5배 |
  | 은송이 | **활공 · 비밀의 힘** — 공중에서 점프를 누르고 있으면 천천히 내려오고, 판마다 다른 다섯 명 중 한 명의 능력이 깃든다(시작 배너에 공개) |

  달리기 동작은 서 있는 그림에서 다리 줄만 바꿔 끼워 만듭니다. 능력은 모두 코스를 쉽게 하는 쪽이라,
  `npm run verify:run`(이단 점프 기준)을 통과한 코스는 어느 캐릭터로든 깰 수 있습니다.
- **조작**: `Space`/`↑` 점프, 공중에서 한 번 더 누르면 이단 점프. `↓` 슬라이드(공중에선 빨리
  내려오기). `Esc` 일시정지. 터치 화면은 왼쪽 아래 `SLIDE`, 오른쪽 아래 `JUMP` 버튼.
  땅 끝을 지나고도 잠깐(코요테 타임) 땅 점프로 쳐주고, 착지 직전에 누른 점프는 기억했다 착지하자마자 뜁니다.
- **촘촘한 코스**: 조각 사이 평지는 하트 · 아이템이 나올 때만 짧게(0.47초) 깔고, 장애물 사이는 대개 0.4~0.6초 —
  그냥 달리기만 하는 구간이 길지 않습니다. 구간 안에서도 앞쪽은 낮은 등급, 뒤쪽은 높은 등급이 더 자주 나와
  (예: 1학기 교실 앞 평균 1.25등급 → 시험장 뒤 4.71등급) 오를수록 어려워지는 게 느껴집니다.
- **이단 점프 타이밍**: 조각에 설계 의도(`expect`)를 적어 두고 검증합니다 — quick(타탁: 현수막을 슬라이드로 빠져나오자마자
  높은 장애물, 0.07~0.13초 안에 두 번째 점프) · late(타   탁: 아주 넓은 구덩이, 정점 무렵 0.33초 뒤에만) · dodge(높은 현수막
  밑에선 참았다가 벗어나자마자, 0.27~0.53초 뒤).
- **학점 3등급 · 갈림길**: B(초록 10점) · A(파랑 20점) · A+(금색 30점). 갈림길 조각은 위 길(발판)이 위험하지만 A · A+,
  아래 길은 쉽지만 B — 위에서 떨어져도 아래 길로 떨어질 뿐이라 욕심낼지 고를 수 있습니다.
- **속도는 일정**: 빨라지는 속도 대신 **코스 조각의 등급**으로 어려워집니다. 조각은
  `lib/run/chunks.ts` 에 사람이 짠 패턴(낮은 장애물 · 이단 점프용 높은 장애물 · 슬라이드로 지나가는
  현수막 · 구덩이 · 위아래 두 갈래 길)이고, 구간마다 뽑는 등급이 다릅니다.
- **구간**: 교실 → 복도 → 캠퍼스 → 학생식당 → 중앙도서관 → 시험장 (각 ~70초). 시험장을 지나면
  다음 학기가 한 등급씩 어렵게 다시 시작합니다. 구간마다 배경(먼 배경 0.25배 · 가까운 배경 0.55배
  시차) · 바닥 · 발판 · 장애물 그림이 다르고, 넘어갈 때 배경이 겹쳐 바뀌며 배너가 뜹니다.
- **구간 전용 기믹** (`zones` 가 붙은 조각 — 그 구간에서만, 일반 조각보다 2.5배 자주): 교실 종이비행기
  (머리 높이 → 슬라이드, 발 높이 → 점프) · 복도 굴러오는 청소 카트 · 캠퍼스 통통 튀는 축구공 · 학생식당 날아오는
  식판 · 중앙도서관 떨어지는 책(바닥 그림자로 예고, 떨어진 책은 쌓여서 뛰어넘는다) · 시험장 시험지 뭉치 + 전공책 +
  구덩이. 날아오는 것은 화면 밖에 있을 때부터 오른쪽 끝에 "!" 경고가 뜹니다. 움직임은 시간이 아니라 달린 거리의
  함수(`obstacleAt`)라 검증 스크립트가 게임과 똑같이 시뮬레이션합니다.
- **체력**: 달리는 동안 초당 1.4 씩 줄고, 장애물 -15 · 구덩이 -25, 하트(~16초마다) +25.
  한 대도 안 맞으면 버틸 수 있고 실수가 쌓이면 끝납니다. 구덩이에 빠지면 즉사 대신 체력을 잃고
  땅이 나올 때까지 끌어올려집니다.
- **교수님 추격**: 출석부를 든 교수님이 바로 뒤에서 출발합니다. 부딪히면(-0.34) · 구덩이에 빠지면(-0.45)
  가까워지고, 1.5초 동안 안 다치면 다시 멀어집니다(초당 +0.045, 질주 중엔 +0.25). 잡히면 끝 —
  체력이 바닥나는 것과 함께 두 가지 끝나는 조건입니다. 가까우면 HUD 의 "교수님" 게이지가 마젠타로 깜빡이고
  화면 왼쪽이 붉게 숨 쉽니다.
- **아이템** (~20초마다, 살짝 뛰어야 닿는 높이): ☕ 아메리카노 = 4.5초 무적 질주(1.6배 속도, 장애물을 부수고
  구덩이 위엔 빛나는 다리) · 📖 족보 = 장애물이나 구덩이를 한 번 대가 없이 막아 줌 · 🧲 자석 = 8초 동안 근처
  학점이 날아옴 · 거대화 = 6초 동안 2배 크기로 장애물을 부수며 달림. 부순 장애물마다 +10점.
  HUD 에 쓰는 중인 아이템이 남은 시간 띠와 함께 뜹니다.
- **이펙트**: 점프 먼지 · 이단 점프 고리 · 착지 먼지, 학점 반짝이, 부딪히면 화면 흔들림과 붉은 번쩍임,
  질주 속도선과 잔상, 족보 보호막, 자석 고리, 부서지는 장애물 파편, 머리 위로 떠오르는 글자.
  "움직임 줄이기" 설정이면 화면 흔들림은 생략합니다.
- **점수 = 거리(1m 1점) + 학점(B 10 · A 20 · A+ 30점) + 부순 장애물(1개 20점)**. 학점이 7m 에 하나꼴이라 60~80% 를 먹으면
  점수의 절반 가까이(45~52%)가 학점에서 나옵니다 — 학점(쿠키런의 젤리)이 순위를 가릅니다. HUD 의 SCORE 아래에
  거리 · 학점 · 부수기가 따로 쌓이고, 학점을 먹으면 그 자리에 "+10" 이 뜨며 HUD 학점 칸이 톡 튑니다. 결과 화면은
  "거리 1234m × 1", "학점 128개 × 10" 처럼 계산식 그대로 보여주고, 소개 화면의 HOW TO SCORE 섹션
  (`components/run/ScoreGuide.tsx`, 숫자는 게임 코드의 상수를 그대로 가져옴)이 미리 설명합니다.
  랭킹은 V1 과 같은 `arcade_scores` 를 이어 씁니다. 개인 최고기록은 `localStorage` 키 `gdevfc_woowang_best`.
- **랭킹의 캐릭터 아이콘**: 기록에 어떤 캐릭터로 냈는지(`character`)를 함께 남기고, 랭킹의 순위와 이름 사이에
  캐릭터 픽셀 아이콘을 보여줍니다. `supabase/migrations/0006_arcade_scores_character.sql` 을 실행해야 하며,
  V1 기록은 모두 우왕이로 플레이한 것이라 기본값이 `woowang` 입니다. 마이그레이션 전에도 랭킹 · 등록은 아이콘
  없이 그대로 동작합니다(칸이 없으면 자동으로 예전 방식으로 조회 · 저장).
- **코스 검증**: `npm run verify:run` 이 게임과 같은 물리 함수로 ① 조각마다 1/15초 간격 입력만으로 한 대도 안 맞고
  구덩이에도 안 빠지고 지나갈 수 있는지 ② 그 길에서 아무것도 안 해도 되는 가장 긴 시간 ③ `expect` 조각이 정말 이단 점프를
  필요로 하고 두 번째 점프를 의도한 타이밍에만 통과하는지(타이밍을 하나씩 제한해 가며 확인) ④ 함께 나올 수 있는 모든
  조각 쌍을 평지 없이 이어 붙여도 지나갈 수 있는지를 확인합니다. 조각을 추가 · 수정하면 꼭 돌려서 "모두 통과" 인지
  확인하세요 (`MAX_JUMPS=3` 으로 3단 점프 기준, `SKIP_PAIRS=1` 로 쌍 검사 생략).
- **공개 오락실 랭킹**: 결과 화면에서 이름만 입력하면(로그인 불필요) `arcade_scores`
  테이블(Supabase, 공개 select/insert RLS)에 기록이 남습니다. `components/play/ScoreSubmit.tsx`
  가 등록 폼 + 등록 직후 TOP 10을, `components/play/Leaderboard.tsx` 가 인트로 화면의 TOP 5를
  보여줍니다. 이 테이블만 다른 회원 전용 테이블들과 달리 `to authenticated` 제한 없이 누구나 읽고 쓸 수
  있게 열어뒀습니다 — 옛날 오락실 하이스코어 방식이라 악의적 스팸에 대한 서버측 방지책은 없습니다
  (이름 1~12자, 점수 0~999999 체크 제약만 존재).
- **모바일**: 가로 화면 게임이라 세로로 들면 `components/play/RotateGate.tsx` 가 가로 회전 안내를
  보여줍니다. 게임이 시작되면 `<Frame immersiveMobile>` 로 좁은 화면에서 캔버스가 뷰포트를 채우고,
  나가기는 `Ⅱ` 일시정지 메뉴에서 합니다.

## 미니게임: 뛰어라 우왕이 (`/jump`)

점프킹을 벤치마킹한 탑 오르기. 입구는 주간줴줴(`/weekly-gg`) 목록의 카드입니다 (광장에서는 소파에 앉은 우왕이).

- **조작**: `SPACE`(모바일은 `JUMP` 버튼)를 누르고 있으면 힘이 모이고, 떼는 순간 뜁니다.
  가득 차면(0.6초) 손을 떼지 않아도 저절로 뜁니다. 방향은 힘을 모으는 동안 `← →` / `◀ ▶` 를
  **한 번씩 눌러** 왼쪽 · 위 · 오른쪽 세 칸 중에서 고르고, 손을 떼도 유지됩니다(베타 테스트에서
  "방향키를 계속 누르고 있어야 해서 불편하다"는 의견으로 바꿈). 힘 모으기를 시작할 때 누르고
  있던 방향이 있으면 거기서 출발합니다. 머리 위에 세 방향이 그려지고 고른 쪽만 밝게 빛납니다.
  땅 위에서는 좌우로 걷습니다. 발판은 아래에서 위로는 통과하고 위에서 내려올 때만 밟힙니다.
  크게 떨어지면 착지할 때 잠깐 철퍼덕.
- **벽 없는 월드**: 월드는 폭 576px(57.6m)짜리 가로 원통입니다 — 왼쪽 끝으로 나가면 오른쪽
  끝에서 나옵니다. PC 는 화면 폭이 곧 월드 한 바퀴라 이음새가 화면 끝과 맞물리고, 휴대폰은
  카메라가 우왕이를 따라 옆으로 움직이고, 땅에서 방향을 누르면 그쪽을 더 보여줍니다(다음 발판이
  대개 옆으로 비켜 있어서). 이음새에 걸친 것은 양쪽에 함께 그려 끊김이 없습니다.
- **스프링 점프대**: 곁 발판 일부(30m 이후, 80m 에 하나쯤)가 빨간 스프링이고, 스프링마다 16~26m 위
  옆쪽에 **깃발 꽂힌 착지 발판**이 짝으로 있습니다. 밟으면 `SPRING_VY` 로 튀어 오르고, 가로 속도는
  밟은 지점에서 착지 발판 가운데까지 닿도록 자동으로 맞춰집니다(`springVx`) — 어디를 밟든 같은
  발판에 내려앉아 제자리로 되떨어져 끝없이 튀는 일이 없습니다. 스프링 위 화살표가 날아갈 쪽을
  가리킵니다. 생성기는 스프링의 양 끝·가운데를 밟는 경우를 시뮬레이션해 착지를 확인하고, 이후에
  놓는 발판이 그 비행 경로를 막는 자리에는 놓이지 않게 합니다.
- **새 / UFO**: 정해진 가로 구간을 오가며 부딪히면 반대쪽으로 튕겨 냅니다(`KNOCK_VX/VY`,
  0.8초 무적). 발판에 서 있는 몸 높이와는 겹치지 않게 놓아서 뛰어오를 때만 부딪힙니다.
  2km(우주)부터는 새 대신 UFO.
- **이펙트**: 힘을 모으면 발밑이 빛나며 기운이 피어오르고(연두 → 노랑 → 주황), 뛰는 순간 먼지가
  양옆으로 터지고 바닥에 고리가 퍼집니다(세게 뛸수록 크게). 최대 힘의 60% 이상으로 뛰면 연두 잔상이,
  스프링으로 솟으면 정점까지 금빛 잔상과 별가루가 남습니다. 착지 먼지는 떨어진 높이에 비례하고,
  철퍼덕이면 탑·발판이 잠깐 흔들립니다(움직임 줄이기 설정이면 흔들림 생략). 새에 부딪히면 깃털이,
  UFO 면 불꽃이 튑니다. 모두 장식이라 물리·발판 생성과는 무관합니다(`JumpGame.tsx` 의 `fx*` 함수들).
- **안 죽음**: 떨어져도 게임오버가 없습니다. `ESC` / `Ⅱ` 일시정지 → "여기서 끝내고 기록 남기기"로
  판을 끝내면, 밟고 선 가장 높은 곳(m)이 기록이 됩니다.
- **점프킹식 절망**: 발판은 한 화면(32m)에 7개 남짓. 다음 발판은 거의 언제나 직전 발판의
  **옆**에 놓이고 길은 한 방향으로 흘러가다 가끔 꺾여서, 빗나간 점프 아래는 대개 비어 있습니다.
  일부러 빗나가게 뛴 점프들을 시뮬레이션해 보면 저층에서 절반이 30m 이상, 최악은 땅까지 떨어집니다.
- **발판 생성과 길 보장** (`lib/jump/world.ts`): 오르는 길(메인 발판 사슬)은 한 줄입니다.
  새 메인 발판은 직전 발판에서 **실제 점프를 시뮬레이션해서** 닿는 게 확인된 자리에만 놓입니다(출발 지점 × 세 방향 × 모든 차징 단계,
  사람이 맞출 수 있게 연속된 차징 단계 여러 개가 성공해야 통과). 게임 화면과 생성기가 같은
  1/120초 고정 스텝 물리 함수(`stepAir`)를 써서 둘이 어긋나지 않습니다. 사이사이 곁 발판을
  섞되, 놓을 때마다 그 발판이 가로챌 수 있는 고리들을 다시 시뮬레이션해서 길을 가로막으면
  버립니다(스프링도 "목표가 아닌 곳에 먼저 닿음"으로 쳐서 길을 끊지 못하게 함). 게임 화면은
  한 프레임에 생성에 4ms 까지만 쓰고, 세 화면 높이를 미리 만들어 둡니다.
  난이도(발판 폭·간격·허용 오차)는 고도 3km 까지 서서히 오르고 그 뒤로는 그대로입니다.
  허용 오차는 같은 출발점·방향에서 연속으로 성공해야 하는 차징 단계 수로, 저층 8단계(≈67ms)에서
  3km 4단계(≈33ms)까지 좁아집니다.
- **고도 구간** (`ZONES`): 숲 0m → 산맥 250m → 구름 550m → 구름 위 900m → 성층권 1400m →
  우주 2000m 부터 1km 마다 수성·금성·지구·화성·목성·토성·천왕성·해왕성·명왕성 → 11km 이후 심우주.
  앞쪽 구간은 짧게, 우주부터는 1km 간격입니다. 1m = 10px, 가득 모은 점프 ≈ 12m.
- **배경** (`lib/jump/background.ts`): 화면 가운데 하늘 끝까지 이어진 탑, 양옆으로 고도에 따라
  시차를 두고 가라앉는 숲·산맥, 스쳐 가는 구름과 발아래 깔리는 구름 바다, 성층권의 지구 가장자리,
  우주의 별과 행성. 무거운 그림(산 능선·숲·구름 바다·탑 벽돌·행성)은 처음 한 번 구워 둡니다.
- **화면**: 세로는 늘 32m 를 보여주고, 가로는 화면 비율에 맞춰 넓어집니다(넓은 화면은 양옆 풍경까지).
  휴대폰은 **세로 그대로** 플레이하며, 터치 화면에서만 화면 아래 `◀ JUMP ▶` 버튼이 나옵니다.
- **랭킹**: `jump_scores` 테이블 (`supabase/migrations/0005_jump_scores.sql` — 달려라 우왕이와
  점수 단위가 달라 테이블을 분리). 개인 최고기록은 `localStorage` 키 `gdevfc_jump_best`.

## 주간줴줴 — 게임 게시판 (`/weekly-gg`)

동아리원이 만든 게임을 계정 없이 바로 플레이하는 "길드 의뢰 게시판". 게임 한 편이 의뢰서 한 장이다.
광장 입구는 분수 옆 소파에서 게임기를 하는 우왕이. 달려라·뛰어라 우왕이도 이 목록에 있다(`play.type: "page"` — 카드가 `/play`, `/jump` 로 바로 간다).

- `/weekly-gg` 목록 · `/weekly-gg/<id>` 플레이+소개+조작법 · `/weekly-gg/submit` 게임 제출
- 정보는 `data/weekly-gg.json` 의 `games`, 빌드는 `public/wgg-builds/<id>/` (페이지 경로 `/weekly-gg/<id>/` 와 겹치면 export 때 서로 덮어쓰므로 폴더를 따로 둔다)

### 게임 추가

1. 빌드를 `public/wgg-builds/<id>/` 에 넣는다 (진입 파일은 `index.html`).
2. `data/weekly-gg.json` 의 `games` 에 한 항목을 더한다. `play.type` 이 내보이는 방식을 정한다.

| `play.type` | 쓰는 경우 | 필요한 값 |
|---|---|---|
| `web` | HTML5 · Unity WebGL — 페이지 안 iframe 에서 실행 | `src`, `aspect`("16 / 9"), `mobile`, (`scroll`) |
| `download` | Windows exe 등 — zip 을 `public/wgg-builds/downloads/` 에 두고 버튼으로 받는다 | `file`, `size`, `run` |
| `soon` | 빌드를 아직 못 받은 게임 | `note` |

- **Unity WebGL** 은 압축을 끈(Compression Format: Disabled) 빌드를 쓴다. `.gz`/`.br` 빌드는 서버가 `Content-Encoding` 헤더를 맞춰 줘야 실행되는데, 압축을 풀어 올리면 그 문제가 없다(전송 압축은 호스팅이 한다). `index.html` 은 기존 `castee/index.html` 을 복사해 파일 이름만 바꾸면 로딩 진행률이 바깥 페이지의 로딩바로 전달된다.
- 소개가 한 문단으로 모자라면 항목에 `guide` 를 더한다 — `steps`(제목·설명·세부 항목)가 번호 붙은 "플레이 방법"으로, `note` 가 그 아래 한 줄로 나온다 (`golem` 항목 참고).
- `web` 의 `src` 는 폴더 주소(`/wgg-builds/<id>/`)로 적는다. Vercel 은 `.../index.html` 을 404 로 돌린다.
- ▶ PLAY 를 누르기 전에는 빌드를 받지 않는다.
- iframe 은 게임과 홈페이지가 서로 방해하지 않게 하는 용도다. 세이브(localStorage · IndexedDB) 때문에 같은 출처로 열어두므로 보안 경계는 아니다 — **운영진이 확인한 빌드만 올린다.**
- 파일 하나가 100MB 를 넘으면 GitHub 가 받지 않는다. 큰 빌드는 외부 저장소(예: GitHub Releases)에 두고 `file` 에 그 주소를 적는다.

### 게임 제출

`/weekly-gg/submit` 폼은 구글 드라이브 링크를 지원 폼과 같은 Formspree 로 보낸다(메일 제목 `[주간줴줴 게임 제출] 제목`, 답장 주소 = 제출자 이메일). 받은 빌드를 확인한 뒤 위 순서대로 직접 올린다.

## 폰트

- **Press Start 2P** (Google Fonts) — 영문 픽셀 헤딩
- **Galmuri** (jsDelivr) — 한글 픽셀 폰트. Press Start 2P 에 한글 글리프가 없어 필요합니다
- **DM Mono** (Google Fonts) — 시스템 바, 캡션
- 본문 한글은 Pretendard → 시스템 고딕 순으로 폴백

`--font-pixel` 은 `'Press Start 2P', 'Galmuri11'` 순으로 지정돼 있어, 글리프 단위 폴백으로
영문은 Press Start 2P · 한글은 Galmuri 로 각각 렌더링됩니다. 히어로처럼 큰 텍스트는
`--font-pixel-lg` (Galmuri14) 를 씁니다.

`▸` `▪` `◂` `【 】` 같은 글리프는 어느 픽셀 폰트에도 없어 본문 폰트로 따로 렌더링합니다.

|---|---|
